    V2 通信与协议（V2X）¶

    版本信息

    Created by SunZhu 2023-10-09 Version 1.4.0

    Last Update：2026-11-17 16:30

    • 补入 PC5 资源调度与消息集体积估算。

    车路协同的技术底座是通信。要回答的是：信息怎么从路侧或他车传到车上，够不够快、够不够准、够不够安全。

    1. 通信要解决什么¶

    需求 场景 通信含义
    超视距感知 弯道、坡道、遮挡路口 把"看不见的"变成"知道的"
    非视距协同 大车遮挡、隧道出口 依赖他车/路侧上报
    群体协同 编队、协同变道、绿波通行 多方状态与时序对齐
    全局调度 云控平台下发策略、限速、路线 大范围、非实时

    V2X 是四类链路的总称：V2V（车-车）、V2I（车-路）、V2P（车-人）、V2N（车-网）。

    2. 技术路线：DSRC 与 C-V2X¶

    维度 DSRC（IEEE 802.11p） LTE-V2X（PC5） NR-V2X（5G 侧链路）
    标准化 IEEE / ETSI（欧洲、美国早期） 3GPP R14（2017） 3GPP R16（2020）
    组网 自组织，无需基站 可无网直连（mode 4）或基站调度（mode 3） 支持单播/组播/广播
    时延 低（直连） 低（直连，典型 10–20 ms 空口） 更低，面向 3–5 ms 级
    可靠性 中，高密度下碰撞严重 较好，有资源调度机制 目标 10⁻⁵ 级 PER
    演进 停滞 在网、可平滑升级 面向高阶协同
    中国路线 仅 ETC（5.8 GHz）规模化 主推 逐步引入

    国内的选择很明确：C-V2X 为主线。原因是蜂窝产业链成熟、可复用基站与运营体系、能平滑演进到 5G。 ETC 是另一条已经跑通的 DSRC 路线（5.8 GHz，收费场景），42.ETC+车路协同 里的资料讨论的就是 "如何用 ETC 的存量基础设施做车路协同"，属于务实派思路。

    3. 两个接口：PC5 与 Uu¶

            ┌────────── PC5（直连，不经基站）──────────┐
  OBU ──┤  车-车 / 车-路 直通，低时延、不依赖覆盖  ├── RSU
        └──────────────────────────────────────────┘
              │ Uu（蜂窝，经基站）
              ▼
         基站/核心网 ──▶ 云控平台 / MEC
    接口 时延 覆盖 适用
    PC5 低（10–20 ms 级） 视距数百米，受遮挡影响 碰撞预警、路口协同、编队
    Uu 较高（数十至数百 ms） 广域，依赖网络覆盖 云端调度、远程监控、OTA、大数据回传

    关键认知：安全类应用必须走 PC5（时延可控），信息服务类可以走 Uu。 把所有业务都堆到 Uu 上，是很多方案"演示能用、实车不敢用"的原因。

    4. 资源分配与拥塞控制¶

    LTE-V2X 的 PC5 有两种资源模式：

    • mode 3（基站调度）：由基站统一分配资源，适合有网络覆盖、需要 QoS 保障的场景；
    • mode 4（分布式）：终端自己"听"信道（sensing）后选择资源，用半持续调度 SPS周期占用， 适合无覆盖或路侧场景。

    高密度下的核心问题是信道拥塞：车多了消息互相碰撞，可靠性断崖下跌。工程上用两个量控制：

    指标 含义 处理
    CBR（信道忙比） 信道被占用的比例 超过阈值就降发送频率/降功率/降 MCS
    CR（信道占用比） 本车占用资源的比例 与 CBR 联动做自适应

    高密度场景是 V2X 的真实考场

    演示时 10 台车很漂亮，真实路口早晚高峰几百个终端同时发 BSM，碰撞率飙升。 所以标准里规定了消息发送频率随密度自适应（如拥堵时从 10 Hz 降到 2 Hz），这是必答题不是加分项。

    5. 消息体系（应用层的骨架）¶

    中国体系以 T/CSAE 53 系列为核心（对应国际的 SAE J2735）：

    消息 全称 内容 谁发
    BSM Basic Safety Message 位置、速度、航向、加速度、刹车、车身尺寸、历史轨迹点 车（周期性，1–10 Hz）
    SPAT Signal Phase and Timing 信号灯当前相位、剩余时间、下一相位 路侧/信号机
    MAP Map Data 路口几何、车道连接关系、停止线 路侧（静态，周期广播）
    RSI Road Side Information 路侧交通事件与标志（施工、限速、事故） 路侧
    RSM Road Side Message 路侧感知到的交通参与者（位置/速度/类型/ID） 路侧（周期性）

    编码：ASN.1 定义结构，UPER 编码压缩体积（BSM 可压到几十字节级），这对空口效率至关重要。

    应用数据 ──ASN.1 定义──▶ UPER 编码 ──▶ PC5 空口 ──▶ 解码 ──▶ 应用
                            ▲
                    体积小、解析快，但可读性差，调试需专用工具

    6. 时延预算：从事件到提示¶

    环节 典型耗时 说明
    传感器采集与感知 30–80 ms 路侧相机曝光 + 检测推理
    融合与决策 10–20 ms 多设备融合、事件判定
    编码与排队 1–5 ms UPER 编码 + 发送队列
    空口传输（PC5） 10–20 ms 受资源调度与重传影响
    车端解码与 HMI 5–15 ms 解码 + 校验签名 + 提示
    合计 约 60–140 ms 尚未计入跨系统时钟偏差

    对照：60 km/h 下 100 ms ≈ 1.7 m 位移；120 km/h 下 ≈ 3.3 m。这就是为什么时延要按场景定预算， 而不是笼统说"低时延"。

    7. 安全体系（V2X 的信任基础）¶

    V2X 消息必须解决三件事：身份可信、内容完整、隐私可控。

    根 CA ──▶ 注册 CA（RC）──▶ 假名 CA（PC）
   │            │                  │
长期身份    入网注册            批量签发假名证书（短期、可轮换）
                                    │
                            消息签名 ──▶ 接收方验签 ──▶ 通过才采信
    机制 作用 工程代价
    假名证书轮换 防轨迹追踪，保护隐私 证书存储与切换管理复杂
    签名/验签 防伪造与篡改 验签算力开销大，高密度下是瓶颈
    撤销列表（CRL） 吊销恶意/失陷设备 列表分发与时效性
    异常行为检测 识别虚假消息（如伪造位置） 需要与感知交叉校验

    验签是隐藏的性能瓶颈

    每辆车每秒可能收到数百条 BSM，每条都要验签。软件验签撑不住时，必须上硬件安全模块（HSM/SE） 或做批量验签优化。这也是很多方案在实验室跑得好、上路就掉帧的原因。

    8. 部署与覆盖¶

    参数 工程取值 说明
    RSU 间距（城市路口） 300–500 m 视距与遮挡决定，路口需重点覆盖
    RSU 天线高度 6–10 m 太低被遮挡，太高覆盖边缘场强弱
    隧道/高架 需专项设计 泄漏电缆或定向天线，多径严重
    时间同步 PTP/gPTP，微秒级 跨设备融合的前提
    坐标系 WGS84 V2X 消息用 WGS84，与国内互联网地图（GCJ-02）不同，必须转换

    9. 5G 与边缘计算¶

    • UPF 下沉 + MEC：把用户面和处理能力放到靠近路口的位置，把 Uu 侧时延压到 10–20 ms 级；
    • 网络切片：为车联网划专用资源，避免与普通流量争抢；
    • NR-V2X：面向编队、协同驾驶等更高要求场景，支持单播与组播，可靠性目标 10⁻⁵。

    现实约束：5G 覆盖与 MEC 部署成本高，目前多数项目仍是"PC5 保安全 + 4G/5G 传数据"的组合。

    10. 评价指标¶

    指标 典型要求 说明
    端到端时延 安全类 <100 ms（P95） 必须写清统计口径
    可靠性（PER） 10⁻² ~ 10⁻⁵ 按应用分级
    覆盖距离 300–800 m（视距） 与天线、功率、遮挡强相关
    时延抖动 越小越好 抖动比均值更影响体验
    并发容量 每 RSU 支持终端数 高密度路口的硬指标

    11. 工程上的坑¶

    1. 坐标与时间戳不统一：V2X 用 WGS84 + UTC，车端用 ENU + 本地时基，不转换就融合必错。
    2. 互操作性：不同厂商 OBU/RSU 的协议实现差异（字段可选性、默认值、异常处理），跨厂商测试是必做项。
    3. 把 Uu 当安全通道：网络拥塞或切换时延抖动，安全类预警会失去意义。
    4. 签验算力低估：高密度下验签拖垮主控，表现为"消息收到了但提示晚了"。
    5. 只测静态场景：实验室空口指标漂亮，一上真实路口（多径、遮挡、高密度）全崩。

    12. 待研究¶

    • 高密度路口的 CBR 实测分布，决定了消息频率该降到多少才合理？
    • 假名证书轮换与验签开销之间，有没有更优的工程折中（如分组证书）？
    • PC5 与 Uu 的双链路切换策略：什么条件下切、切的时候怎么保证不丢关键消息？
    • ETC 存量设施改造为车路协同的成本与收益，在国内是否有可复制的样板？
