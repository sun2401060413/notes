    T1 交通流与运行安全理论¶

    版本信息

    Created by SunZhu 2023-08-20 Version 1.4.0

    Last Update：2026-11-17 16:30

    • 补入基本图参数取值、拥堵消散与运行状态评价口径。

    车路协同的收益最终落在三个可量化的账上：少死伤、少堵、少排放。 技术指标要翻译成交通与安全的语言。

    1. 交通流基础：先理解"路"的物理规律¶

    1.1 基本图（Fundamental Diagram）¶

    流量 q (veh/h)
   ▲
   │        ╭──── 通行能力 C
   │      ╱   ╲
   │    ╱       ╲   ← 拥堵分支（q 随密度上升反而下降）
   │  ╱           ╲
   └────────────────────▶ 密度 k (veh/km)
        自由流         拥堵

    关系式：q = k \cdot v。经典 Greenshields 模型假设速度随密度线性下降：v = v_f(1-k/k_j)， 代入得 q = v_f(k - k^2/k_j)，最大值即通行能力 C = v_f k_j / 4。

    工程含义：一旦越过临界密度进入拥堵分支，增加车流反而降低通行量——这就是"越堵越慢、越慢越堵"的数学解释， 也是为什么"让车流匀速"（如 GLOSA）比"让车快点"更有效。

    1.2 拥堵波¶

    车队中一次刹车会向后传播并放大，形成向后传播的冲击波（shockwave）。V2X 编队/协同巡航的价值之一， 就是把"逐车反应"改造为"同步反应"，压缩波速与放大效应。

    1.3 服务水平（LOS）¶

    用密度、速度、延误等划分 A–F 六级，是道路设计与验收的通用语言。做方案时把它和"平均速度""延误" 对齐，才能和业主/设计院沟通。

    2. 安全：从"感觉"到"可算"¶

    2.1 冲突与替代安全指标（SSM）¶

    事故是小概率事件，直接统计事故率要等太久，所以用接近失事的程度来度量风险：

    指标 定义 适用
    TTC 按当前速度相撞所需时间 追尾、直行冲突
    PET 两车先后通过同一冲突点的时间差 交叉口冲突（不要求同轨迹）
    DRAC 避免冲突所需减速度 衡量"是否需要急刹"
    MTTC 修正后的 TTC（考虑加速度） 更贴近真实制动行为

    实践中：TTC < 2.7 s 常作为预警线、< 1.5 s 作为紧急线；PET < 1 s 视为严重冲突。 这些阈值要按场景标定，不能全局一套。

    2.2 安全标准体系¶

    标准 管什么 关键点
    ISO 26262 功能安全（E/E 系统失效） ASIL A–D，要有安全目标与安全机制
    ISO 21448（SOTIF） 预期功能安全（能力不足但系统正常） 处理"感知不到/决策不会"这类风险
    ISO 21434 网络安全 威胁分析与风险评估（TARA）
    UL 4600 自动驾驶安全案例（Safety Case） 论证"为什么可以上路"的整体框架
    国内标准族 准入、测试、道路测试管理 与《道路测试与示范应用管理规范》配套

    SOTIF 是自动驾驶特有的难点：系统没坏，但摄像头在逆光下就是看不见——这不算功能失效，却是真实风险。 处理方式是把"能力边界"显式建模，并为每一种已知不足设计降级策略。

    2.3 ODD、MRC 与运行监控¶

    ODD 内运行 ──▶ 边界识别（接近退出条件）──▶ 请求接管 ──▶ 接管失败 ──▶ MRC（最小风险状态）
    • ODD 必须可判定：不能是"天气良好"这种模糊描述，要是"降雨量 < X mm/h 且能见度 > Y m"；
    • 接管要有预警时间：研究普遍认为需要数秒级（不是 1 秒），否则人类驾驶员来不及；
    • MRC 要有物理保障：靠边停车也要保证不撞、不挡应急车道。

    3. V2X 应用的能力分级¶

    这是把"通信能力"翻译成"交通收益"的关键框架：

    级别 能力 典型应用 对通信的依赖
    L1 信息提示 告知驾驶员 红绿灯倒计时、前方施工、限速提醒 低（Uu 即可，秒级）
    L2 协同感知 扩展感知范围 路口冲突预警、盲区预警、弱势交通参与者提示 中（PC5，100 ms 级、1–10 Hz）
    L3 协同决策 给出建议/协商 GLOSA 车速建议、协同变道、匝道汇入 高（低时延 + 一致性）
    L4 协同控制 直接参与控制 编队行驶、协同自适应巡航、云控调度 极高（毫秒级 + 高可靠）

    绝大多数已落地项目停在 L1–L2。L3/L4 的瓶颈不只在通信，更在责任划分与跨厂商协同机制。

    4. 效率评价：别只说"更畅通"¶

    指标 定义 用途
    平均行程时间 / 延误 实际用时 − 自由流用时 最直观的效益指标
    行程时间可靠性 行程时间的 90/95 分位与中位数差 比平均值更能体现"确定性"价值
    停车次数/怠速时间 路口启停次数 GLOSA 的直接收益
    绿波带宽 干道协调控制的可用带宽 信号优化方案的核心
    通行能力提升 饱和流率变化 编队/协同巡航的收益

    效益测算要设对照组

    车路协同项目的效益常被高估，因为缺少同期对照。严谨做法是同路段、同时段、同流量条件下对比， 或做仿真基线（SUMO/VISSIM）与实测双验证。

    5. 验证：怎么证明"足够安全"¶

    仿真（百万级场景） ──▶ 封闭场地（可控极端场景） ──▶ 公开道路（真实交通） ──▶ 影子模式（量产车静默验证）
    • 里程与置信度：靠自然里程证明"比人类安全"需要天文数字的里程，业界共识是必须用场景化 + 加速测试替代纯里程堆砌；
    • 场景库：按 ODD 分解为功能场景 → 逻辑场景 → 具体场景，用参数化覆盖边界；
    • 对抗测试：主动构造加塞、鬼探头、施工改道等长尾；
    • 影子模式：新模型与线上模型并行，只记录不执行，用差异挖掘 badcase。

    6. 合规与数据¶

    议题 要点
    测绘资质 高精地图采集与制作需导航电子地图制作甲级测绘资质，这是国内 HD Map 的准入门槛
    地理信息安全 坐标偏移（GCJ-02）、敏感地物脱敏、地图审图号
    数据出境 涉及测绘/位置数据出境有严格限制，跨国车企尤其敏感
    个人信息 车外人脸/车牌需脱敏，行车数据属个人信息范畴
    事故责任 国内已明确 L3 试点阶段的责任划分框架，协同驾驶场景仍在探索
