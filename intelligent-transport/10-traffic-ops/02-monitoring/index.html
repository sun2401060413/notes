    T2 路网运行监测与事件检测¶

    版本信息

    Created by SunZhu 2023-11-06 Version 1.3.0

    Last Update：2026-11-17 16:30

    • 补入事件检测的分层架构与误报抑制手段。

    没有可靠的"看见"，后面的研判与管控都是空转。 两件事：常态运行状态怎么测准、异常事件怎么尽快发现。

    1. 监测体系的分层¶

    路网级（区域/全省）   ── 拥堵指数、行程时间可靠性、事件热力
   ▲
路段级（两点之间）     ── 区间速度、密度、排队长度、行程时间
   ▲
断面级（一个点位）     ── 流量、点速度、占有率、车头时距
   ▲
车辆级（个体）         ── 轨迹、车牌、车型、行为（急刹/变道）

    层级不能跳：只有断面流量就想算路段密度，必须借助"流量守恒 + 平均车长"假设，误差会放大。 诚实做法是标注"推算值"并给出置信区间。

    2. 数据源对比¶

    数据源 测什么 精度 覆盖 成本 主要问题
    线圈/地磁 流量、占有率、点速度 流量高，速度低 点位 中（需破路） 易损坏、维修贵
    微波/毫米波雷达 流量、多车道速度 中高 点位 中 遮挡、跨道误判
    视频（枪机/球机） 流量、速度、轨迹、事件 依赖标定与算法 点位/路段 低（复用监控） 夜间与恶劣天气衰减
    雷视一体 流量 + 全息轨迹 高 点位/路段 较高 标定要求高
    激光雷达 高精度轨迹 很高 点位 高 成本、雨雾衰减
    ETC 门架 断面流量、行程时间（配对） 高（对 ETC 车） 路段 低（已有） 只覆盖装 ETC 的车
    浮动车/GNSS 路段速度、行程时间 中（样本偏差） 全网 低 网约车/货车样本偏置
    手机信令 OD、人群 粗 全网 中 隐私、精度差

    工程建议：点位用"视频 + 雷达/雷视"互补（视频管事件与分类，雷达管速度与全天候）， 路段用 ETC 门架 + 浮动车做行程时间，全网红绿灯用浮动车兜底。没有单一源能同时满足精度、覆盖与成本。

    3. 交通参数的算法与陷阱¶

    参数 定义 陷阱
    流量 q 单位时间通过断面的车辆数 多车道需分车道统计后求和
    时间平均速度 \bar v_t 各车瞬时速度的算术平均 不等于空间平均速度，会低估
    区间平均速度 \bar v_s 距离 / 平均行程时间 反映路段真实状态，用这个报"路段速度"
    占有率 O 车辆占用检测器的时间比例 与密度近似成正比，但受车长影响
    密度 k 单位长度车辆数 很难直接测，靠 q/v 推算
    排队长度 停车队列长度 视频最可靠，检测器需模型推断

    最常被误用的一个公式

    q = k \bar v 里的 \bar v 必须是空间平均速度。用时间平均速度代入会系统性高估流量， 在速度差异大的路段（大车混入）误差可达 10–20%。

    4. 视频交通检测的技术链¶

    相机安装(俯角/高度/焦距) ──▶ 透视标定(像素↔米) ──▶ 检测 ──▶ 跟踪 ──▶ 轨迹 ──▶ 参数与事件
                                                    │
                                             跨镜重识别（多杆拼接时）

    4.1 标定是地基¶

    • 像素→世界坐标：已知车道宽度、标线间距、相机安装高度与俯角，用消失点或四点法标定；
    • 标定误差 1 像素在 100 m 处可能就是 20–30 cm，所以远处目标的速度估计不可信；
    • 相机被风吹动、清洁后位置变化，都要重新标定——建议把"标定自检"做成日常任务。

    4.2 检测与跟踪¶

    • 检测：YOLO 系列在边缘设备上是性价比首选；远距离小目标靠高分辨率 + 切片；
    • 跟踪：ByteTrack/BoT-SORT 类方法，靠轨迹连续性分配 ID；
    • 轨迹后处理：平滑、去抖、航向估计、速度估计（多帧拟合比单帧差分稳）。

    5. 事件检测¶

    5.1 事件类型与判定逻辑¶

    事件 判定依据 典型阈值 难点
    车辆停驶 轨迹速度持续为 0 且位置不变 停车 >10–30 s（按路段等级） 拥堵时大量误报
    逆行 航向与车道方向夹角 >120° 持续 >3 帧 掉头、车道方向标定错会误报
    慢行/异常低速 速度显著低于断面均值 < 均值的 40% 拥堵与事故难区分
    行人/非机动车闯入 类别 + 出现在禁行区 置信度 >0.6 夜间、小目标
    抛洒物 静止小目标出现在车道上 尺寸 + 位置 与阴影、路面污渍混淆
    拥堵 速度 < 阈值且持续 速度 <20 km/h 持续 5 min 常发性拥堵需与事件拥堵区分
    交通事故 停车 + 散落物 + 异常轨迹组合 多条件融合 需人工复核确认
    烟火（隧道） 视觉 + 温感 — 隧道照明干扰

    5.2 三条技术路线¶

    路线 原理 优点 缺点
    背景建模 帧差/高斯混合，检测前景异常 算力低、易部署 光照突变、树影、雨雪大量误报
    目标检测 + 规则 检测框 + 轨迹规则（停/逆/慢） 可解释、可调 依赖检测质量
    端到端事件识别 视频片段分类/时序模型 能识别复杂事件（事故） 样本少、可解释性差

    现实组合：规则打底（覆盖 80% 常见事件）+ 模型补充（复杂事件）+ 人工复核（最后一公里）。

    5.3 评价指标（这是招标与验收的关键）¶

    指标 含义 参考目标
    检出率（召回） 真实事件中被发现的比例 ≥90%（交通事件）
    误报率 每天每路/每百公里的误报条数 越低越好，这是可用性关键
    平均检测时间 事件发生到系统报警 <10 s（隧道/高速）
    定位精度 报警位置与实际位置偏差 <50 m
    复核工作量 每百条报警需人工判断的比例 越低越好

    招标文件里最该盯住的一条

    很多项目只写"检出率 ≥95%"，不写误报率。结果系统每天几千条误报，值守人员直接关闭告警。 要求"误报率 ≤ N 条/路/天"比要求检出率更有意义。

    6. 部署形态：边缘还是中心¶

    形态 优势 局限 适用
    边缘（路侧/前端） 带宽省、时延低、断网可用 算力受限、运维分散 事件检测、实时预警
    中心（云） 算力充足、模型可升级、跨点位分析 依赖网络与带宽 轨迹融合、跨镜追踪、大模型研判
    云边协同 边缘粗筛 + 中心精判 架构复杂 主流推荐

    7. 数据质量与运维（最容易被忽略）¶

    1. 镜头污染：灰尘、雨渍、蛛网会导致长期"假盲"，需自动检测画面质量（清晰度、遮挡、偏移）。
    2. 夜间与逆光：白天调好的参数夜间不可用，需分时段阈值。
    3. 标定漂移：见 4.1，建议每周自检。
    4. 时钟不同步：多杆数据融合前必须统一时基，否则轨迹拼接会错位。
    5. 数据断档：要有断点续传与缺失标记，不能让"没数据"被当成"没事件"。

    8. 与上下游的接口¶

    上游供给 本域输出 下游使用
    检测器/视频/气象/ETC 断面参数、轨迹、事件、路况 T3 主动安全（风险辨识）、T4 管控（优化输入）、T5 应急（事件触发）
    车路协同路侧感知 全域轨迹（RSM） 补盲、跨镜贯通
    车辆上报（V2X/车联网） 急刹、ESP、雨刷、雾灯状态 反向印证路面与环境状态
