    I3 产业链与企业¶

    版本信息

    Created by SunZhu 2024-08-20 Version 1.1.0

    Last Update：2026-11-17 17:50

    • 按"芯片—设备—边缘—平台—集成—运营"分层梳理产业链；
    • 补入各环节的竞争要素与议价关系。

    一个车路协同项目里，设备只是成本的一小部分；真正决定成败的是集成方能否把六七个厂商的东西拼成一个能运维的系统。

    1. 产业链分层¶

      芯片/模组 ──▶ 设备制造 ──▶ 边缘计算 ──▶ 平台与云 ──▶ 集成与实施 ──▶ 运营与运维
  通信基带      RSU/OBU        MEC 节点      云控平台       总集/分包        路段运营方
  感知芯片      相机/雷达      路侧算力      数据中台       弱电施工         技术服务商
  定位模组      信号机/诱导    边缘网关      算法服务       联调测试         数据服务商
        │                                                                       │
        └──────────────────── 业主（交通/交管/城投）定义需求与验收 ───────────────┘

    分层不是绝对的：头部设备商往往同时做平台与集成，运营商既做网络也做总集。判断一个厂商的位置，看它在哪一层有不可替代的能力，而不是看它宣传的业务范围。

    2. 各环节的竞争要素¶

    环节 核心能力 格局特点 议价能力
    芯片与模组 通信基带、感知算力、功耗与车规认证 集中度高，V2X 模组是少数玩家的市场 强（缺货时更强）
    路侧设备（RSU、雷视、信号机） 硬件可靠性、防护等级、协议兼容 厂商多、同质化明显，价格竞争激烈 中偏弱
    边缘计算 算力密度、散热、多路视频接入 与传统服务器/安防厂商重叠 中
    平台与云 数据治理、接口标准化、并发与稳定性 大厂与行业集成商并存 中偏强（一旦接入难替换）
    集成与实施 多厂商联调、工期控制、验收经验 区域性强，靠项目积累 强（对业主）
    运营与运维 在线率、故障响应、数据质量 目前最薄弱的一环 取决于合同模式

    3. 三个容易被忽略的事实¶

    1. 接口成本高于硬件成本：不同厂商的 RSU、雷视、信号机接入同一平台，联调工作量常超过设备采购额的三成。
    2. 运维决定系统活多久：路侧设备的在线率是第一指标。装完不维护，半年后可用率可能掉到七成以下。
    3. 业主的技术能力决定集成商的自由度：业主有专职技术团队时，方案能做得更细；没有时，集成商倾向于"能验收就行"的最小实现。

    4. 选型时的判断顺序¶

    1. 先看协议兼容：能不能按 T/CSAE 53 的消息集接入，能不能对接业主已有平台；
    2. 再看在线率与售后：同城有没有备件与服务团队，故障响应承诺写进合同没有；
    3. 再看性能指标：感知距离、检测精度这些要在现场复测，不看彩页；
    4. 最后看价格：前三项不过关时，低价换来的是后期返工。
