    M2.1 领域全景与演进脉络¶

    1. 先把边界划清楚¶

    这套资料里，「自动驾驶」「智能网联汽车」「车联网」「车路协同」四个词高频混用，含义并不等价：

    概念 英文/缩写 内核 回答的问题
    自动驾驶 AD / Autonomous Driving 车辆自主完成感知-决策-控制 车自己能不能开
    智能网联汽车 ICV 自动驾驶 + 网联通信能力 车能不能和外界交换信息
    车联网 IoV / V2X 网络 车-车/车-路/车-人/车-云的信息通道 信息怎么传、传给谁
    车路协同 CVIS / 车路云一体化 路侧感知 + 边缘计算 + 云控平台与车端协同 靠"路"能不能补"车"的短板

    包含关系可以这样记：自动驾驶 ⊂ 智能网联汽车；车联网是 ICV 的通信底座；车路协同是"用路侧和云端的能力去放大车端能力"的一种系统级方案。

    本库资料的重心在车路协同（40.~48. 共 5 个目录、约 380 篇），Apollo/Autoware 等单车智能内容作为技术底座（15.、18.，约 170 篇）。

    2. 两条技术路线的十年拉锯¶

                    单车智能（Tesla / Waymo 路线）              车路协同（中国方案）
感知来源      摄像头+毫米波+（激光雷达）为主              车端 + 路侧多源感知 + 云控
解决长尾      靠数据规模与算法迭代                        靠路侧视角与超视距（"上帝视角"）
成本结构      单车成本高（激光雷达/大算力）              单车成本可降，但路侧基建投入前置
商业模式      卖车/卖软件（订阅）                          基建投资 + 运营服务 + 数据增值
最大风险      长尾永远清不完                               谁来建、建完谁运营、跨区域不互通

    几点来自本库资料的判断（可对照 40.车路协同/99.车路协同报告、资料/、44.C-V2X/参考资料/）：

    1. 不是二选一，而是分工：车端解决"精细与实时"，路侧解决"超视距与全局"，云端解决"全局调度与数据闭环"。真正落地的是三者协同，缺一环就退化为各自为战。
    2. 路侧的价值密度不均：路口、隧道口、匝道、施工区这类"遮挡 + 冲突密集"的位置，路侧投入产出比最高；长直高速路段收益主要来自超视距预警与准全天候。
    3. 商业闭环仍是最大变量：基建由谁投、运营谁付费、数据如何变现，决定这条路线能否规模化复制。
    4. "重感知轻地图"与"重地图"在收敛：车端 BEV 感知能力上来后，HD Map 从"必需"变成"先验"，但路侧与云控仍需要统一的地图底座来对齐坐标系。

    3. 演进脉络（按"能力—政策—产业"三条线看）¶

    阶段 能力线 政策/标准线 产业线
    2013–2016 概念期 ADAS 量产普及（AEB/ACC/LKA），单车 L2 《中国制造 2025》提出智能网联汽车 Mobileye/Tesla 带动 ADAS 供应链
    2017–2019 协议期 LTE-V2X（3GPP R14）标准完成，V2X 芯片/模组出现 车联网产业发展行动计划；无锡获批首个国家级车联网先导区 OBU/RSU 厂商起步，示范区建设
    2020–2022 系统期 C-V2X 规模测试；路侧雷视融合成熟；云控平台上线 11 部委《智能汽车创新发展战略》；道路测试与示范应用管理规范；双智城市试点 先导区扩围，云控平台与运营主体出现
    2023–2024 落地期 车路云一体化架构收敛；BEV/Occupancy 上量；端到端开始试水 智能网联汽车准入和上路通行试点；车路云一体化应用试点城市 城市级项目打包招标，运营模式开始分化
    2025 以后 规模期 车端算力与路侧算力协同调度；数据闭环与影子模式常态化 标准体系从"缺标准"转向"标准打架与互认" 从"建"转向"用"，考核指标由里程转向事故率/效率

    年份以官方文件为准

    上表用于建立时间感，具体发布机构与文件号请以 30.智能网联车/01.国家规范/、40.车路协同/02.团体标准/ 中的原文为准。 本库习惯：凡是结论都留一个能点开的出处。

    4. 一个可复用的分析框架：四问法¶

    面对任何一个车路协同项目/方案/新闻，按这四问拆解，基本能避开 90% 的忽悠：

    1. 触发条件是什么？ 靠什么感知（车端/路侧/云端）、判定阈值多大、误报怎么抑制。
    2. 时延预算够不够？ 从事件发生到车端提示的总时延，与场景允许的反应时间比。
    3. 坐标系与时间戳怎么对齐？ 跨设备融合的前提，也是大多数"演示很好、实车不行"的根因。
    4. 谁付钱、怎么验收？ 建设方、运营方、考核指标是否闭环。

    5. 延伸问题（留给自己的待研究清单）¶

    • 路侧感知的标定漂移在真实路口几个月后有多大？有没有低成本的在线自检手段。
    • 车路云一体化的责任划分：协同失效导致事故，责任在车、在路、还是在运营方？
    • 跨城市互认的技术障碍到底在协议、在证书体系，还是在数据格式？
    • 端到端大模型上车后，车路协同的价值主张需要怎么重写？
