    M3.1 阅读路线与使用指南¶

    这一页回答两个问题：怎么读、怎么往库里加内容。

    1. 知识库与归档区的分工¶

    维度 归档区（本地 auto-driving 素材盘） 知识库（本仓库 docs/intelligent-transport/）
    内容 原始素材：摘录、白皮书、方案、报告 经过提炼、重组、有论述的知识
    组织 按来源与话题堆放，允许重复、允许残缺 按 M/T/V/A/S/I 六域与编号组织，一篇只讲清一件事
    忠实度 忠于原文，不做加工 允许判断与取舍，不确定处明确标注
    用途 写作时的依据、查证时的原始出处 日常学习、检索、写方案的主入口
    是否公开 不公开，只在本机 随站点发布，可分享、可检索

    一句话：素材是原料，知识库是产品。

    同一份素材往往能从不同角度支撑不同节点（讲路侧设备的手册里有标定方法，讲标准的文件里有工程约束）， 所以知识库不做"一篇素材对一个页面"的镜像，也不给素材建索引—— 找素材靠归档区自己的目录和全文搜索，知识库里只出现"被消化过"的内容。

    2. 五条阅读路线¶

    路线 A：主专业线（运行管控 / 主动安全）¶

    1. M1 知识网络框架 → M2.1 领域全景
    2. T1 交通流与运行安全理论
    3. T2 路网运行监测与事件检测
    4. T3 主动安全管控（核心）
    5. T4 交通管控与信号优化

    路线 B：车路协同线（系统与建设）¶

    1. V1 车路协同体系架构
    2. V2 通信与协议
    3. S1 感知与传感器（重点看第 6 节"路侧感知的特殊性"）

    路线 C：AI 线（能力补齐）¶

    1. A0 人工智能域路线图
    2. S1 感知与传感器（补齐视觉与融合的概念底座）
    3. 按 A0 列出的知识缺口，到归档区与外部补齐

    路线 D：支撑技术线（地基）¶

    • 定位：S2 定位与时空基准
    • 规划控制：S3 车端决策规划与控制
    • 仿真与孪生：S4（待写）

    路线 E：产业与项目线（写方案 / 做汇报）¶

    T3 主动安全管控 + I1 标准与规范（待写）+ 归档区里的招投标与建设方案， 按"依据—技术—案例"三段直接拼装成方案骨架。

    3. 在库内怎么检索¶

    方式 用法
    编号直达 知道是 T3.2，就去 T3 主动安全管控 找对应小节
    场景链 M1 第 4 节 的 4 条跨域链路，按业务问题串节点
    术语对照 M2.2 术语与概念体系，先统一口径再讨论
    全文搜索 站点右上角搜索框；或编辑器内全库搜索

    4. 新增一个专题的标准动作¶

    1. 登记：在 M1 框架表 确认或新增编号，避免同一件事写两处；
    2. 成文：按固定骨架写——定义与边界 → 原理 → 方法与方案对比 → 工程要点 → 常见误区 → 待研究；
    3. 挂钩：至少写 2 条与相邻节点的交叉引用（如 T3 与 V2、S1）；
    4. 留白：末尾列"待补内容"，把没想清楚的部分显式记下来，不用空话填满；
    5. 回填：更新 index.md 完成度表与 M1 现状表。

    5. 写作规范¶

    • 一段只讲一个观点，先结论后论证；
    • 表格用于对比（方案、指标、阈值），不用于堆信息；
    • 数字必须带口径：均值还是 P95、统计窗口、样本量；
    • 不确定就写"待核实"，不编造标准和数据；
    • 加粗写成 **文字**，且内侧不要紧贴全角括号或引号——**ESKF（误差状态卡尔曼滤波）** 不会渲染（Markdown 的 flanking 规则）， 应改写为 **ESKF 误差状态卡尔曼滤波** 或 **半持续调度 SPS**；
    • 引用外部素材时在正文里点名（如"某省团雾治理方案"），但不在库里为素材建目录；
    • 中文与数字之间加空格，专有名词保留原文。

    6. 维护节奏¶

    周期 做什么
    每月 把新读到的东西归到某个编号下写成小节；素材照旧放回归档区
    每季 回看各章的"待补内容"，挑一条补齐
    每年 审一遍框架：该合并的合并、该拆的拆，编号只增不改
