    S3 车端决策规划与控制¶

    版本信息

    Created by SunZhu 2024-09-02 Version 1.2.0

    Last Update：2026-11-17 16:30

    • 补入交互博弈与安全模型的选择。

    感知回答"世界是什么样"，规划回答"我该怎么走"，控制回答"方向盘和油门给多少"。 这一层把信息变成动作，也是安全责任最集中的地方。

    1. 经典分层架构¶

    Routing(全局路由) ──▶ Behavior(行为决策) ──▶ Motion Planning(轨迹规划) ──▶ Control(横纵向控制)
   车道级路网          变道/跟车/让行/停车        一条带时间的最优轨迹         油门/刹车/转向
   秒级~分钟级           0.1~1 s 级                 10 Hz 重规划               50–100 Hz

    每层的时间尺度差一个量级，这个结构不是历史包袱，而是为了在不确定环境中保持可控性： 上层慢、下层快，上层给意图，下层保安全。

    层 输入 输出 典型方法
    Routing 起终点、地图 车道序列 A*/Dijkstra、分层图搜索
    Behavior 感知目标、地图、交规 行为指令（跟车/换道/借道） 状态机、决策树、POMDP、博弈
    Motion Planning 参考线、动态障碍预测 轨迹 (x,y,\theta,v,a,t) Frenet 采样、EM Planner、iLQR、MPC
    Control 轨迹 + 车辆状态 油门/制动/转角 PID、Pure Pursuit、Stanley、LQR、MPC

    2. 行为决策¶

    2.1 三种实现范式¶

    范式 代表 优点 缺点
    规则/状态机 早期量产 ADAS、Apollo 部分场景 可解释、可验证、易过审 场景爆炸，维护成本随规则数指数上升
    概率决策 POMDP、MDP 显式处理不确定性 计算量大，状态空间需离散化
    学习/博弈 逆强化学习、博弈论交互 拟人、能处理交互 可解释性差，安全兜底难

    工程现实：量产车普遍是"规则为主 + 学习辅助 + 安全监控"的组合，纯学习方案在责任认定上还过不了关。

    2.2 路口交互的核心¶

    无保护左转、环岛、匝道汇入，本质是多智能体博弈：你的决策改变对方的行为，对方的行为又改变你的收益。 常见做法是把交互建模为"预测-评估-再预测"的迭代，或用 IDM/MOBIL 这类跟驰-换道模型生成对手的响应。

    3. 路径与轨迹规划¶

    3.1 图搜索（路由层）¶

    算法 完备性 最优性 用途
    Dijkstra 完备 最优 无权/等权代价，路网规模小时可用
    A* 完备 最优（启发函数可采纳） 主流，靠启发函数剪枝
    RRT/RRT* 概率完备 渐近最优 高维、非结构化环境（泊车、越野）

    3.2 Frenet 坐标系¶

    把道路拉直：以参考线为 s 轴（纵向弧长）、法向为 l 轴（横向偏移），三维规划降为"纵向-横向"解耦问题。

    \ddot{s} = a_s,\qquad \ddot{l} = a_l - \kappa \dot{s}^2

    其中 \kappa 是参考线曲率——曲率不连续会让横向加速度跳变，这是乘客晕车的常见来源。

    3.3 采样 vs 优化¶

    路线 代表 特点
    采样 Lattice、Frenet 多项式采样 简单、实时性好，代价函数设计决定质量
    动态规划 + 二次规划 Apollo EM Planner（先 DP 粗解 → QP 精修） 兼顾全局与平滑，工程主流
    直接优化 iLQR、MPC、梯度法 精度高，对初值与约束敏感

    MPC 的标准形式：

    \min_{u_{0:N-1}} \sum_{k=0}^{N-1} \left( \|x_k-x_k^{ref}\|_Q^2 + \|u_k\|_R^2 \right) \quad \text{s.t.}\quad x_{k+1}=f(x_k,u_k),\ u_k\in\mathcal{U},\ x_k\in\mathcal{X}_{safe}

    约束里塞的就是"安全"：车道边界、曲率上限、加速度/加加速度（jerk）上限、与障碍物的距离下界。

    4. 控制¶

    方法 适用 要点
    PID 纵向速度、简单横向 参数好调，抗扰一般
    Pure Pursuit 低速、大曲率（泊车/园区） \kappa = 2\sin\alpha / L_d，预瞄距离 L_d 随速度自适应
    Stanley 中高速循迹 前轮转角 = 航向误差 + 横向误差项，对横向偏差敏感
    LQR 线性化轨迹跟踪 有明确代价权重，稳定性可分析
    MPC 高速、需处理约束 能显式约束转角/加速度，算力开销大

    量产常用横纵向解耦：横向用 LQR/MPC 跟轨迹，纵向用 PID/MPC 跟速度曲线。 解耦的前提是低速（<5 m/s 时耦合效应不能忽略）。

    5. 安全模型¶

    模型 思路 用途
    TTC 阈值 碰撞时间低于阈值就预警/制动 AEB/FCW，简单有效
    RSS（Responsibility-Sensitive Safety） 形式化定义"谁该负责"，给出安全距离公式 可证明的安全包络
    安全走廊/可达集 计算车辆未来可达集合，取不与障碍相交的控制 高速场景的兜底

    RSS 的安全距离（纵向跟车）大意是：

    d_{safe} = v_r\rho + \tfrac{1}{2}a_{max}\rho^2 + \frac{v_r^2}{2b_{min}} - \frac{v_f^2}{2b_{max}}

    其中 \rho 是反应时间，b 是制动能力。它的价值不在精确，而在于把"安全"从感觉变成可验算的约束。

    6. 车路协同如何改变规划¶

    这是本主线最该关注的一条线：路侧/云端的超视距信息把"被动响应"变成"主动预判"。

    应用 机制 对规划的改变
    绿波车速引导（GLOSA） 下发信号灯相位与时序（SPAT） 纵向规划从"跟随前车"变成"按信号优化到站时间"，减少怠速
    路口冲突预警 路侧感知全域目标（RSM） 提前减速/让行，处理遮挡导致的"鬼探头"
    协同变道/汇入 邻近车辆意图共享（BSM） 博弈从"猜测"变成"协商"，减少保守抖动
    施工/事故预警 路侧事件 + 静态信息（RSI） 提前重路由，而不是到跟前才发现封路
    编队/协同通行 云端调度 队列间距可压缩，提升通行能力

    协同规划的三个前提

    1. 时延可补偿：消息晚到 200 ms 就要按目标速度和时戳外推，否则规划用的是"过去的世界"；
    2. 失效可降级：V2X 断连时必须无缝退回单车感知，不能出现"没有 V2X 就不会开"；
    3. 责任可界定：协同决策出的轨迹，责任在车还是在云，必须有明文约定。

    7. 评价指标¶

    维度 指标 说明
    安全 碰撞率、near-miss 率、TTC 分布、最小安全距离 用仿真 + 影子模式统计
    舒适 jerk（加加速度）、横向加速度峰值、加速度变化率 建议 jerk < 3 m/s³（舒适）、< 5 m/s³（可接受）
    效率 通行时间、平均速度、停车次数、延误 与信号配时联动评估
    合规 违章次数、压实线、超速 需按当地交规
    稳定 重规划频率、轨迹跳变率、退出接管率（MPI） MPI 是 L4 的核心 KPI

    8. 工程上的坑¶

    1. 参考线跳变：路由切换或地图更新导致参考线不连续，轨迹会"抖一下"。要做参考线平滑与切换时的位姿对齐。
    2. 规划频率与感知频率不同步：感知 10 Hz、规划 10 Hz 但相位不同，需时间对齐与预测补偿。
    3. 不确定性没有传下去：感知给了协方差，规划却当确定性用——这是"看着像没问题，实际很危险"的典型。
    4. 保守与效率的调参地狱：同一个参数在通畅路段太保守、在拥堵路段太激进，需要按场景分档而非全局一套。
    5. 仿真过了不等于实车过：仿真里的对手太"讲理"，实车上的对手会加塞、会犹豫。
