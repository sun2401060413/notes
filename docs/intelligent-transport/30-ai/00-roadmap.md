# A0 人工智能域路线图与关键概念

> 编号 **A0**。这一域的作用是"能力放大器"：让监测更准、研判更快、方案更省人。
> 但要清醒：**AI 在交通里能拿分的地方很具体，吹得越大越难落地。**

## 1. AI 在智能交通里的三种角色

| 角色 | 做什么 | 成熟度 | 代表任务 |
| --- | --- | --- | --- |
| 感知（代替眼睛） | 从图像/点云中提取结构化信息 | 高（工程化充分） | 检测、跟踪、车牌、事件识别 |
| 理解（代替部分判断） | 把多源信息变成结论 | 中 | 事故判别、风险评分、报告生成 |
| 决策（协助或代替调度） | 给出策略建议 | 低（责任与稳定性未解） | 信号优化、应急调度建议 |

**现实排序**：感知 ≫ 理解 > 决策。投入产出比最高的永远是"把感知做稳"，而不是"上一个大模型"。

### A1 计算机视觉基础

| 专题 | 要掌握 | 交通落点 |
| --- | --- | --- |
| A1.1 检测 | 单阶段/两阶段、anchor-free、NMS 及其替代、小目标策略 | 车辆/行人/抛洒物检测 |
| A1.2 分割 | 语义/实例/全景、可行驶区域 | 路面病害、积水、抛洒物区域 |
| A1.3 多目标跟踪 | 数据关联、Kalman、两阶段关联（ByteTrack 类） | 轨迹生成（一切分析的基础） |
| A1.4 ReID | 特征嵌入、跨镜检索 | 车辆跨杆追踪、逃费稽核 |

### A2 交通视觉专项

- **车牌/车型/车标**：OCR 已成熟，难点在夜间、逆光、污损、大角度；
- **事件视觉识别**：停车、逆行、抛洒物、行人闯入、烟火（对应 T2.3）；
- **长尾**：施工、事故、异形货物——样本少，靠主动学习挖。

### A3 时序与预测

| 任务 | 方法 | 用途 |
| --- | --- | --- |
| 轨迹预测 | 社会力/LSTM/VectorNet/Transformer | 冲突预判、危险行为识别 |
| 交通流预测 | ARIMA/时空图网络（GCN+RNN） | 管控前馈、诱导预案 |
| 异常检测 | 重构误差、密度估计 | 未知类型事件发现 |

**注意**：交通流预测的精度天花板不高（15 min 内尚可，1 h 以上基本靠不住），
方案里要写清预测时域与误差范围。

### A4 大模型与多模态

| 能力 | 能不能用 | 说明 |
| --- | --- | --- |
| 视频/图像理解（VLM） | 可用（辅助） | 生成事件描述、检索相似画面、辅助复核 |
| 文本报告生成 | 可用 | 事件简报、日报、方案初稿 |
| 知识问答（RAG） | 可用 | 标准条文检索、历史案例检索 |
| 直接做检测/测量 | 不建议 | 精度与时延都不如专用小模型 |
| 直接下发管控指令 | 不可 | 责任与可解释性都不满足 |

!!! warning "大模型的定位"
    在交通管控里，大模型最合适的角色是**研判助手与文档工人**：
    把结构化的专业判断（阈值、规则、模型）留给小模型和规则引擎。
    让它直接控制信号灯或发布限速，目前过不了安全与责任这一关。

### A5 Agent 与智能体

| 专题 | 形态 | 交通场景 |
| --- | --- | --- |
| A5.1 工具调用 | LLM + 函数调用（查库/算指标/调接口） | "查一下 G50 K120 段今天的事故与平均速度" |
| A5.2 多智能体 | 角色分工（监测/研判/处置/复盘） | 事件处置流程自动化 |
| A5.3 管控 Agent | 感知-决策-执行闭环 | 分级预警的自动升级与建议 |
| A5.4 安全与可解释 | 白名单、人机确认、审计日志 | **落地前提**，不是可选项 |

**Agent 在交通领域的落地条件**：① 有明确的操作边界；② 每一步可审计；
③ 关键动作必须人工确认；④ 有回滚。

## 3. 与 T/V 域的咬合点（避免"为 AI 而 AI"）

| 业务问题（T/V） | AI 能贡献什么 | 不该由 AI 做什么 |
| --- | --- | --- |
| T2.3 事件检测 | 视觉识别、异常发现 | 直接判定责任 |
| T3.1 风险辨识 | 冲突识别、行为预测 | 决定限速档位（需规则与规范） |
| T3.5 预警发布 | 生成文案、选择通道 | 直接发布未审核内容 |
| T4 信号优化 | 到达预测、参数推荐 | 直接改配时（需仿真验证 + 人工确认） |
| T5 应急处置 | 预案匹配、资源调度建议 | 自动派单（需授权） |
| V3.2 雷视融合 | 目标检测与关联 | 替代标定与同步 |

## 4. 选型判断：什么时候**不要**用 AI

| 场景 | 更合适的做法 |
| --- | --- |
| 阈值明确的判定（超速、逆行） | 规则 + 几何计算，稳定可解释 |
| 数据量小（<1000 样本） | 传统方法或迁移学习，别硬训大模型 |
| 需要严格时延（<50 ms） | 小模型 + 量化，远离大模型 |
| 需要可解释与可审计 | 规则优先，模型辅助 |
| 一次性分析（写报告） | 大模型正好 |

## 5. 本域的知识缺口

这一域目前只有骨架，正文几乎是空的。按优先级列出要补的子主题：

1. **交通视觉**：车辆重识别（VeRi 类数据集）、交通事件数据集与赛题、车牌识别的工程细节（夜间/污损）；
2. **轨迹预测**：Argoverse/nuScenes 预测任务、VectorNet 类方法、交互建模的取舍；
3. **交通流预测**：时空图网络综述、公开数据集（PEMS、METR-LA）与误差基准；
4. **大模型**：VLM 视频理解的实测能力边界、RAG 工程实践、领域微调的数据与算力门槛；
5. **Agent**：工具调用框架、多智能体协作范式、可审计与人机确认机制；
6. **部署**：边缘侧 INT8 量化实操、TensorRT/OpenVINO 的坑、算力与帧率的换算。

## 6. 学习路径建议

1. **先补 A1.3 跟踪**：一切轨迹分析的基础，也是最容易被低估的一环；
2. **再做 A2.2 事件识别**：与 T2.3 直接咬合，能立刻产生业务价值；
3. **然后 A6 工程化**：把模型真正跑到边缘设备上，这一步决定方案能不能交付；
4. **最后碰 A4/A5**：先用 RAG 做"标准与案例检索"这种低风险场景，再考虑研判辅助。
