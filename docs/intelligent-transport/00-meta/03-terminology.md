## 1. 系统与架构

| 术语 | 全称/英文 | 含义与约定用法 |
| --- | --- | --- |
| ODD | Operational Design Domain | 设计运行域。**一切自动驾驶讨论的前提**，脱离 ODD 谈 L3/L4 没有意义 |
| MRC | Minimum Risk Condition | 最小风险状态。系统退出时的兜底策略（靠边停车/降速/移交） |
| 车路云一体化 | Vehicle-Road-Cloud Integration | 车端、路侧、云端三层协同的系统架构，2024 年后成为国内主流表述 |
| 云控平台 | Cloud Control Platform | 区域级中心系统：汇聚路侧数据、下发调度与预警、支撑监管与运营 |
| 边缘计算 | MEC, Multi-access Edge Computing | 部署在路侧/近端的算力节点，承担低时延感知与融合 |
| 智路OS | Smart Road OS | 面向路侧的开放操作系统/中间件（百度等推动），屏蔽硬件差异、统一接入 |
| 双智 | 智慧城市基础设施与智能网联汽车协同发展 | 城市级试点口径，强调"车城联动"而非单点道路改造 |
| 先导区 | 国家级车联网先导区 | 工信部批复的区域性试点载体，配套标准验证与规模部署 |

## 2. 感知

| 术语 | 含义 |
| --- | --- |
| BEV | Bird's Eye View，俯视栅格表示。多相机/多传感器统一到同一平面，便于融合与下游规划 |
| Occupancy（占用栅格） | 把空间离散为体素/栅格并预测占用与语义，天然处理不规则障碍物 |
| 雷视融合 | 毫米波雷达 + 视频的时空对齐融合，路侧最主流的组合（成本 vs 性能平衡点） |
| 4D 成像雷达 | 具备高度维与更高角分辨率的毫米波雷达，输出类点云数据 |
| 前融合 / 特征融合 / 后融合 | 在原始数据层 / 特征层 / 目标层做融合；工程上分别对应"精度最高但最脆弱 / 折中 / 最稳但信息损失大" |
| 标定 | 求传感器内外参。**内参管畸变，外参管位姿，时间同步管对齐**，缺一不可 |
| 手眼标定 | 求解 $AX=XB$ 的经典问题，用于雷达-相机、车体-路侧设备的位姿关系 |
| BEV 时序融合 | 用 ego 位姿把历史 BEV 特征对齐到当前帧，是提升遮挡目标召回的关键 |

## 3. 定位

| 术语 | 含义 |
| --- | --- |
| GNSS / RTK / PPP | 卫星定位 / 实时动态差分（厘米级，需基站或网络 RTK）/ 精密单点定位（无需基站但收敛慢） |
| IMU / INS | 惯性测量单元 / 惯性导航系统。短时精度高、长期漂移，必须与 GNSS 或地图融合 |
| P-Box | 组合导航定位盒子，车规级的"GNSS+IMU+RTK"一体模组 |
| 地图匹配 | 把定位结果吸附到车道级路网上，解决"横向 30 cm 的定位误差在 3.5 m 车道里到底在哪条道" |
| UWB | 超宽带，室内/隧道/停车场等高遮挡场景的补充定位手段，精度 10–30 cm |
| 时空同步 | 多传感器融合的前置条件：PTP/gPTP 硬同步 + 时间戳插值软同步 |

## 4. 通信与 V2X

| 术语 | 含义 |
| --- | --- |
| V2X | Vehicle to Everything，车与车(V2V)、车与路(V2I)、车与人(V2P)、车与网(V2N)的总称 |
| DSRC / ETC | 基于 IEEE 802.11p 的专用短程通信；国内 ETC（5.8 GHz）是已经规模化的 DSRC 变体 |
| C-V2X | Cellular V2X，基于蜂窝（LTE/5G）的车联网技术，含直连与蜂窝两种链路 |
| PC5 接口 | C-V2X 的**直连**侧链路（车-车/车-路直通，不经基站），低时延、不依赖网络覆盖 |
| Uu 接口 | C-V2X 的**蜂窝**链路（经基站），覆盖广、时延较高 |
| LTE-V2X / NR-V2X | 3GPP R14 的 LTE 侧链路 / R16 引入的 5G NR 侧链路，后者面向更高吞吐与更低时延 |
| RSU / OBU | 路侧单元 / 车载单元。RSU 是"路的信息出口"，OBU 是"车的信息入口" |
| BSM | Basic Safety Message，车辆基本安全消息（位置、速度、航向、刹车状态等） |
| RSI / RSM / SPAT | 路侧信息 / 路侧感知目标 / 信号灯相位与时序。**这四个消息是车路协同应用层的骨架** |
| ASN.1 | 消息的抽象语法描述，V2X 消息普遍用 UPER 编码以压缩体积 |
| 假名证书 | V2X 安全体系里定期更换的匿名证书，兼顾可追溯与隐私保护 |

## 5. 地图

| 术语 | 含义 |
| --- | --- |
| HD Map | 高精度地图，厘米级、含车道级几何与语义（车道线、曲率、坡度、限速、路口拓扑） |
| ADAS Map | 辅助驾驶地图，精度与要素弱于 HD Map，但覆盖与更新成本更可控 |
| NDS | Navigation Data Standard，面向**更新与分发**的地图存储标准（分区、增量更新） |
| OpenDRIVE | 面向**仿真与道路描述**的开放格式（道路几何、车道、路口），与 OpenSCENARIO 配套 |
| Lanelet2 | 开源矢量地图框架，语义化车道与交通规则，Autoware 生态常用 |
| ADASIS | 把地图数据"前瞻"推送给车端的接口标准（ADASIS v2/v3） |
| 众包更新 | 用量产车回传的感知结果更新地图，是 HD Map 成本的主要解法 |

## 6. 安全与评价

| 术语 | 含义 |
| --- | --- |
| TTC | Time To Collision，碰撞时间。阈值通常按场景设（如 2.7 s 预警、1.5 s 紧急） |
| PET | Post Encroachment Time，后侵入时间，衡量冲突"险不险"的指标 |
| DRAC | Deceleration Rate to Avoid Crash，避免碰撞所需减速度 |
| SOTIF | ISO 21448，预期功能安全，处理"系统没坏但能力不足"的风险 |
| ISO 26262 | 功能安全，ASIL 等级划分与开发流程 |
| mAP / NDS | 平均精度 / nuScenes 综合检测指标 |
| AMOTA | 多目标跟踪的平均指标（nuScenes 口径） |
| 漏检率 / 误报率 | 工程上比 mAP 更贴近安全与体验，尤其安全类应用 |

## 7. 车端硬件与软件

| 术语 | 含义 |
| --- | --- |
| 域控制器 | 按功能域（智驾/座舱/车身）集中的计算单元，取代分布式 ECU |
| MCU / SOC | 微控制器（实时、低功耗）/ 系统级芯片（高算力，跑感知与规划） |
| AUTOSAR CP / AP | 经典平台（强实时、静态配置）/ 自适应平台（面向 SOA、动态部署） |
| SOA | 面向服务的架构，把功能拆成可复用的服务接口 |
| SOME/IP / DDS | 车载服务通信中间件，前者偏 AUTOSAR 生态，后者偏 ROS 2/高性能场景 |
| T-Box | 车联网终端，负责远程通信、OTA、车辆数据上报 |
| OTA | 空中升级，分 SOTA（软件）与 FOTA（固件） |

## 8. 使用约定

- 缩写首次出现写全称，之后只用缩写。
- 涉及标准时写"标准号 + 年号"，例如 `T/CSAE 53-2020`，不写"那个团标"。
- 厂商名统一用官方中文名，产品名保留原文（如 MDC、Apollo、OpenV2X）。
- 数字带单位，物理量统一 SI；时延一律写端到端并注明统计口径（均值/P99）。
