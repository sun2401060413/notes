## 1. 框架构成

领域内容按两级组织：**域 → L1 主题群 → L2 专题**，每个节点给唯一编号，编号不复用。

纯树形结构的问题是同一件事只能挂一处。工程里"路口冲突预警"同时涉及运行管控（安全应用）、
车路协同（协同感知）、人工智能（目标检测与轨迹预测）、支撑技术（感知与通信），
挂在任一域都会漏掉其余视角。因此结构上取**树形骨架 + 网状关联**：

```text
        树形：负责"找得到"                网状：负责"想得全"
   ┌──────────────────────┐        ┌──────────────────────────┐
   │ 域 → 主题群 → 专题   │   +    │ 跨域链路 / 交叉引用       │
   └──────────────────────┘        └──────────────────────────┘
              编号唯一                      一个场景串起 4–6 个节点
```

树负责定位，链路负责还原真实问题的全貌（见第 4 节）。

## 2. 六域总览

| 代码 | 域 | 关注对象 | 在库中的位置 |
| --- | --- | --- | --- |
| **M** | 元知识 | 框架、领域全景、术语口径、写法约定 | 视角 |
| **T** | 运行管控 | 路网运行状态，以及如何让它更安全、更顺畅 | 主专业 |
| **V** | 车路协同 | 车与路的协同方式，系统怎么建、怎么运营 | 主战场 |
| **A** | 人工智能 | 用什么模型把数据变成判断与决策 | 能力放大器 |
| **S** | 支撑技术 | 被多域复用的底层技术：感知、定位、平台、安全 | 工具箱 |
| **I** | 产业与治理 | 标准、政策、产业链、典型项目 | 落地约束 |

!!! tip "主次关系"
    **T 是目的，V 是手段，A 是工具，S 是基础，I 是边界。**
    项目问题先落到 T（要解决什么交通问题），再找 V/A/S 的组合，最后用 I 校验合规与可交付性。

## 4. 跨域链路

每个真实问题都是一条跨域链路，下面四条是常见业务的原型。

### 链路 1：高速公路团雾预警与限速

```text
T2.4 气象感知（能见度检测）
   └─▶ T3.1 风险评估（能见度-车速-制动距离模型）
          └─▶ T3.2 速度管控（分级限速策略）＋ T3.5 预警发布（VMS/广播/V2X）
                 └─▶ V2.2 通信（RSI 事件下发）＋ V4.2 预警应用（车端提醒）
                        └─▶ I1 标准（团雾预警阈值是否有国标依据）＋ S6 合规
```

### 链路 2：城市路口冲突预警

```text
A1.3 多目标跟踪 ＋ A2.4 行人识别
   └─▶ V3.2 雷视融合（路侧感知）
          └─▶ T3.1 冲突分析（TTC/PET 判定）
                 └─▶ V2.3 RSM 消息 ──▶ V4.2 车端预警
                        └─▶ T3.6 效果评价（冲突率下降多少）
```

### 链路 3：重点营运车辆（两客一危）动态管控

```text
T2.2 轨迹与重识别 ＋ T3.3 重点车辆管控
   └─▶ V1.2 云控平台（车辆画像与轨迹回放）
          └─▶ A3.1 轨迹预测（风险行为预判）
                 └─▶ T3.5 分级预警（车端/企业/监管三端）
                        └─▶ T5 应急处置（事件闭环）
```

### 链路 4：干线绿波 + 车路协同车速引导

```text
T4.2 干线协调（配时方案）
   └─▶ V2.3 SPAT 消息（相位与时序）
          └─▶ V4.3 GLOSA 车速引导
                 └─▶ S3.2 纵向规划（按信号优化到站时间）
                        └─▶ T1.3 评价（延误/停车次数/油耗）
```

## 5. 编号与写法约定

### 5.1 编号怎么用

| 用途 | 写法 | 示例 |
| --- | --- | --- |
| 文档命名 | `NN.英文短名.md`，NN 与 L1 顺序对应 | `03-active-safety.md` |
| 文内引用 | 直接用编号 | "见 T3.2 速度管控" |
| 标签 | `#T3.2`，用于检索与打标 | `T3.2 V4.2` |

### 5.2 新内容归到哪里

1. 解决什么**交通问题** → 先归 T 域；
2. 靠什么**系统/协同**实现 → V 域；
3. 用了什么**模型/算法** → A 域；
4. 依赖什么**底层技术** → S 域；
5. 受什么**标准/政策/商业**约束 → I 域；
6. 拆不准的放 M4.3 暂存，日后归位。

### 5.3 合并与拆分

- 同一主题跨两域时，正文写在主属域，另一域只留一行索引与链接，不复制内容。
- 编号只增不改；确需废弃时标注"已并入 X"，保留编号占位。
- 一篇文档讲清一件事，超过一个主题群就拆，小于半页就并入相邻专题。
