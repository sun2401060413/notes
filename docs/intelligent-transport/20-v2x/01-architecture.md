# V1 车路协同体系架构与演进

> 编号 **V1**。车路协同不是"车 + 路"的物理叠加，而是一套**分层解耦、能力互补**的系统架构。
> 这一章先立架构，再挂各个专题（V2–V7）。

## 1. 四层架构

```text
┌──────────────────────────── 中心/云层 ────────────────────────────┐
│ 云控平台 · 交通管控平台 · 数据中台 · 高精地图发布 · 安全证书管理    │
│ 职责：全局调度、跨区协同、数据沉淀、监管对接、模型训练              │
└───────────────▲───────────────────────────────┬──────────────────┘
                │ 汇聚（Uu/专线）                │ 下发策略/事件
┌───────────────┴───────────────────────────────▼──────────────────┐
│                        路侧/边缘层                                │
│ RSU · 雷视一体 · 边缘计算单元 · 信号机 · VMS · 气象/路面传感器      │
│ 职责：本地感知、融合、事件判定、低时延直连推送（PC5）               │
└───────────────▲───────────────────────────────┬──────────────────┘
                │ PC5 直连（车-路）              │
┌───────────────┴───────────────────────────────▼──────────────────┐
│                          车端层                                   │
│ OBU/T-Box · 域控制器 · 感知/规划/控制 · HMI · OTA                  │
│ 职责：接收协同信息、融合自身感知、执行决策                          │
└──────────────────────────────────────────────────────────────────┘
                ▲
                │ 通信底座：C-V2X（PC5 直连 + Uu 蜂窝）、时间同步、安全证书
```

**三层各有明确分工**：边缘保"低时延与本地自治"，中心保"全局与沉淀"，车端保"最终安全执行"。

## 2. 数据流：三条主链路

| 链路 | 方向 | 内容 | 时延要求 |
| --- | --- | --- | --- |
| 感知上行 | 车/路 → 中心 | 车辆状态（BSM）、路侧目标（RSM）、事件、视频 | 秒级可接受 |
| 指令下行 | 中心 → 路/车 | 管控策略、限速、路径诱导、事件预警（RSI） | 分钟级（策略）/ 秒级（事件） |
| 直连协同 | 路 → 车（PC5） | 冲突预警、信号相位（SPAT）、路口地图（MAP） | **百毫秒级** |

!!! note "为什么要保留直连"
    中心链路一旦拥塞或断网，安全类应用就失效。**PC5 直连是"断网也能用"的底线设计**，
    这也是车路协同区别于"车联网信息服务"的根本。

## 3. 云控平台做什么

| 功能域 | 具体能力 |
| --- | --- |
| 接入与汇聚 | 多源设备接入、协议适配、时空对齐、数据质量管理 |
| 监控与运行 | 设备在线率、路口态势、路段运行状态、告警 |
| 协同服务 | 事件下发、限速下发、路径诱导、优先通行申请处理 |
| 数据服务 | 轨迹存储、指标计算、开放 API、与交管/业主系统对接 |
| 运营管理 | 设备台账、工单、运维考核、计量计费 |
| 安全 | 设备认证、证书生命周期、访问控制、审计 |

**云控平台的成败不在功能多少，而在"接了什么、算了什么、给谁用"**。很多平台建完只做展示，
就是因为没有和业务系统（信号、执法、救援）打通。

## 4. 协同应用的分级（V4 的骨架）

| 级别 | 能力 | 例子 | 对系统要求 |
| --- | --- | --- | --- |
| L1 信息提示 | 告诉人 | 红绿灯倒计时、前方施工 | 低（Uu 即可） |
| L2 协同感知 | 扩展感知 | 路口冲突预警、盲区预警 | 中（PC5、100 ms） |
| L3 协同决策 | 给建议/协商 | GLOSA、协同变道、匝道汇入 | 高（一致性 + 低时延） |
| L4 协同控制 | 参与控制 | 编队、云控调度 | 极高（毫秒级 + 高可靠） |

国内已落地项目绝大多数在 **L1–L2**，L3 在示范区/特定车辆上验证，L4 基本处于试验阶段。
做方案时如实分级，比吹"全场景协同"更容易过评审。

## 5. 演进路线与政策抓手

| 阶段 | 特征 | 抓手 |
| --- | --- | --- |
| 示范验证（2018–2020） | 单点示范、封闭/半封闭 | 先导区、测试场 |
| 规模建设（2021–2023） | 城市级覆盖、云控平台上线 | 双智试点、先导区扩围 |
| 一体融合（2024–） | 车路云一体化、跨区互认 | 车路云一体化应用试点城市 |
| 运营深化（趋势） | 从"建"转"用"，考核效果 | 运营补贴、数据服务、保险联动 |

## 6. 与单车智能的关系

| 维度 | 单车智能强 | 车路协同强 |
| --- | --- | --- |
| 精细度 | 近距高精度 | 远距、全局 |
| 遮挡 | 无力 | 俯视补盲 |
| 成本 | 单车成本高 | 基建前置、单车可降配 |
| 迭代 | OTA 快 | 基建周期长 |
| 失效 | 靠自身冗余 | 靠路侧冗余与降级 |

**结论**：不是替代关系。合理架构是"车端为主、路侧补盲、云端统筹"，且必须设计**任一层失效时的降级路径**。

## 7. 建设要点（工程视角）

1. **先定场景，再定设备**：不要先买 RSU 再想做什么应用。
2. **标定与时间是地基**：路侧设备位置、外参、时钟，三项任一不准，上层全废。
3. **网络与电力**：路口取电、光纤回传、防护等级常是工期杀手。
4. **运维体系**：设备在线率、标定漂移、镜头污染，要有常态化巡检与自检。
5. **与既有系统对接**：信号机品牌协议、交管平台接口、业主监控系统，往往比新技术更难。
6. **可评价**：从第一天就设计指标采集，否则一年后无法证明价值。

## 8. 待研究

- 跨城市互认的障碍在协议、证书还是数据格式？有没有已跑通的样板？

- 车端算力上量后，路侧还需要做多少"智能"，还是回归"纯感知 + 转发"？
