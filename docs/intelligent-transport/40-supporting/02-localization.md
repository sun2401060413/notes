# S2 定位与时空基准

> 感知告诉你"周围有什么"，定位告诉你"我在哪"。定位错了，再准的感知也会被投射到错误的位置上。

## 1. 精度需求分级

| 应用 | 横向精度需求 | 说明 |
| --- | --- | --- |
| 导航级 | 5–10 m | 手机导航水平 |
| 辅助驾驶（L2） | 1–3 m | 车道级提示够用 |
| 车道级定位（L3+） | **≤30 cm** | 能分辨"在哪条车道"，是 HD Map 可用的前提 |
| 泊车/场端 | ≤10 cm | 常由场端 UWB/视觉补足 |
| 路侧设备标定 | ≤10 cm | 路侧感知输出质量的地基 |

定位还有一个常被忽略的指标：**完好性**（integrity）——不仅要准，还要能自信地说"现在不准"。隧道出口、城市峡谷里，"错误的自信"比"承认失效"危险得多。

## 2. 坐标系：先统一语言，再谈精度

```text
WGS84(经纬高) ──▶ ECEF(地心直角) ──▶ ENU/UTM(局部平面) ──▶ 车体/传感器
                        │
                        └──▶ 地图坐标系（NDS/OpenDRIVE/自有格式）
```

| 坐标系 | 用途 | 坑 |
| --- | --- | --- |
| WGS84 | 全球经纬高 | 直接用经纬度做距离计算会错（经度 1° ≠ 纬度 1°） |
| ECEF | 跨设备交换的标准中介 | 数值大（10⁶ m 量级），浮点精度要注意 |
| ENU | 局部规划与融合 | **原点选在哪必须写死并全系统一致** |
| UTM | 工程制图、路侧设备位置 | 跨投影带要换带，中央经线一变坐标就跳 |
| GCJ-02 / BD-09 | 国内互联网地图 | 与 WGS84 相差 **50–500 m**，混用直接灾难 |

!!! warning "国内项目最常见的低级错误"
    底图用高德/百度（GCJ-02/BD-09），定位解算用 RTK（WGS84），两者直接叠加 → 目标整体偏移几十米。
    正确做法：统一转到 WGS84 或统一转到 GCJ-02，**只在一个层面做一次转换**，并在数据字典里注明。

## 3. GNSS：从米级到厘米级

| 模式 | 精度 | 依赖 | 收敛 | 适用 |
| --- | --- | --- | --- | --- |
| 单点（SPP） | 3–10 m | 仅卫星 | 即时 | 兜底、粗定位 |
| RTK | 2–5 cm | 基准站/网络 RTK，需数据链路 | 秒级 | 车端主力、路侧标定 |
| PPP | 10–30 cm | 精密星历，无需基站 | 10–30 min | 无基站区域 |
| PPP-RTK | 5–15 cm | 精密星历 + 区域改正 | 分钟级 | 大规模部署的折中 |

误差源按影响排序：**电离层/对流层延迟 > 多路径 > 星历与钟差 > 接收机噪声**。城市峡谷与树下最大的敌人是**多路径**，表现为"位置忽然跳几米然后回来"。

RTK 的可用性高度依赖基准站距离与数据链路，工程上必须准备**降级链路**：RTK 失效 → PPP/SPP + IMU 惯导推算 → 地图匹配纠偏，并明确各级降级能撑多久。

## 4. IMU 与组合导航

IMU 输出角速度与加速度，积分得姿态、速度、位置。误差随时间是**累积发散的**：

- 陀螺零偏 → 姿态漂移（deg/h 级），姿态误差又会把重力错误地投影进加速度；
- 加速度计零偏 → 位置误差随时间**二次发散**；
- 所以纯惯导只能撑很短时间（消费级几十秒、车规级几分钟），必须与 GNSS/轮速/视觉融合。

**ESKF 误差状态卡尔曼滤波**是组合导航的主流实现：以误差为状态量，线性化更准、数值更稳。典型融合量：

| 观测 | 抑制的误差 | 备注 |
| --- | --- | --- |
| GNSS 位置/速度 | 位置、速度发散 | 城市峡谷中需按质量加权或直接剔除 |
| 轮速 + 方向盘 | 速度、航向 | 低成本方案的主力，打滑时失效 |
| 静止检测（ZUPT） | 零偏估计 | 等红灯、堵车时是宝贵的标定窗口 |
| 视觉/地图匹配 | 横向误差 | 解决"纵向准、横向飘"的问题 |

!!! tip "杆臂补偿"
    GNSS 天线、IMU、后轴中心不在同一点，高速转弯时位置差可达几十厘米。
    必须接入**杆臂 lever arm**参数并在融合中补偿，否则转弯时定位会"甩一下"。

## 5. 地图匹配与 HD Map 定位

GNSS/RTK 在城市峡谷、隧道、高架下会失效，此时靠"感知到的车道线/路沿/杆状物"与 HD Map 匹配来定位：

```text
感知要素（车道线/路沿/标志） ──▶ 与地图矢量做配准 ──▶ 位姿修正
                    ▲
            初值来自 IMU/轮速推算（局部连续）
```

工程要点：
- 匹配要**有置信度**：匹配不上时宁可输出"降级"，不要硬凑；
- 匹配结果通常是**约束**而非绝对位置，适合做滤波的观测而非直接赋值；
- 车道线残缺/施工改道是主要失效场景，需与地图更新节奏配合。

## 6. UWB 与其他补充手段

| 手段 | 精度 | 场景 | 局限 |
| --- | --- | --- | --- |
| UWB | 10–30 cm | 隧道、停车场、室内、场端 | 需布基站，非视距（NLOS）误差大，成本随覆盖线性增长 |
| 视觉重定位 | 10–50 cm | 有先验视觉地图的区域 | 受光照/季节影响 |
| 激光点云匹配 | 5–20 cm | 有先验点云图的路段 | 依赖高精地图鲜度 |
| 磁钉/导轨 | 厘米级 | 固定线路（BRT、港口） | 基建成本高，不灵活 |

**UWB 的核心难点不是测距，是多基站时钟同步与 NLOS 识别**：TDOA 方案要求基站间同步到纳秒级，
而金属反射环境里的 NLOS 会让解算跳点，需要残差检验剔除。

## 8. 时间同步（定位的隐形前提）

定位输出必须带**时间戳**，且与感知、通信共用一个时基：
- PTP/gPTP 硬同步到微秒级；
- 融合时按时间戳插值到统一时刻（例如所有观测都插值到当前帧时刻）；
- V2X 消息里带的时间戳要和本地时基对齐，否则路侧目标"位置对、时间错"，融合后目标会跳。

## 9. 评价指标

| 指标 | 含义 | 备注 |
| --- | --- | --- |
| RMS / CEP50 / CEP95 | 水平误差的统计量 | 报 P95 比均值诚实 |
| 可用率 | 满足精度阈值的时长占比 | 分场景统计（开阔/峡谷/隧道） |
| 收敛时间 | 从启动/失锁恢复到可用精度的时间 | 隧道出口是关键场景 |
| 完好性 | 漏警率、误警率、保护级 | 安全相关场景必看 |
| 航向精度 | 度（°） | 低速时航向最难，泊车场景尤其 |

## 10. 工程上的坑

1. **天线位置写错**：GNSS 主天线必须装在车顶最高点、远离金属遮挡，装错位置比选错设备影响更大。
2. **单天线无航向**：静止或低速时航向不可观，必须靠双天线或 IMU+磁力计，否则起步瞬间方向乱跳。
3. **坐标系混用**：见第 2 节，国内项目最高频事故。
4. **RTK 断链无降级**：只报"定位失效"而不做推算和纠偏，体验会断崖式下降。
5. **路侧设备的绝对位置**：路侧 RSU/相机的位置要用 RTK 打点并**定期复测**，这个基线错了，后面全错。
